# Browser/Web Agents: What Actually Works



## 1. Benchmarks and current results

**Online-Mind2Web + WebJudge** → 300 live tasks / 136 sites; evaluation is a 3-stage judge: (a) extract task "key points", (b) select key screenshots from the trajectory, discarding uninformative frames, (c) judge outcome from task + key points + selected screenshots + action history. → o4-mini WebJudge hits **85.7% agreement with humans, 3.8% mean SR gap**; WebJudge-7B **87%** agreement, beating prior autoraters at 73.9–79.4%. Human-eval agent scores: **Operator 61%**, Claude Computer Use 3.7 **56.3%**, most others **28–30%**. Difficulty cliff (Operator): easy (≤5 steps) **83.1%** → medium (6–10) **58.0%** → hard (≥11) **43.2%**. Key diagnostic: **failed tasks take ~2× the steps of successful ones** — agents loop, they don't give up. → [arXiv 2504.01382, Apr 2025, COLM 2025](https://arxiv.org/abs/2504.01382); [repo](https://github.com/OSU-NLP-Group/Online-Mind2Web); [alphaXiv overview](https://www.alphaxiv.org/overview/2504.01382). Evaluation hygiene from the repo: start from the specified site (not Google), include only *factual* actions in history, use o4-mini as judge.

**Current Online-Mind2Web leaderboard** (Steel.dev, updated Jun 29 2026): Browser Use Cloud "bu-max" **97.0%** (Mar 2026, *self-reported with a custom Claude-Agent-SDK judge*), GPT-5.4 native computer use **93.0%**, ABP + Claude Opus 4.6 **90.53%** (all 300 results public; prior SOTA 78.7%), TinyFish **90.0%**, UI-TARS-2 **88.2%** (Sep 2025), Yutori Navigator **78.7%** human-eval but **64.7%** under WebJudge. → [leaderboard.steel.dev](https://leaderboard.steel.dev/leaderboards/online-mind2web/). **Treat the top of this board as unusable for comparison** — the Navigator 78.7 vs 64.7 split is the same agent under two judges.

**WebArena** (2307.13854): original baseline 14.41%, human 78.24%. WebPilot (MCTS global+local optimisation) **37.2%**, +93% relative over concurrent tree-search methods → [arXiv 2408.15978, Aug 2024, AAAI 2025](https://arxiv.org/abs/2408.15978). Steel's tracked WebArena SOTA is **74.3%** (WebTactix/DeepSeek-v3.2, Jun 2026).

**BrowserGym/AgentLab** — the only apples-to-apples cross-benchmark table. Claude 3.5 Sonnet: MiniWoB 69.8, WorkArena-L1 56.4, **L2 39.1** (vs GPT-4o 8.5), **L3 0.4**, WebLINX 13.7, WebArena 36.2, VisualWebArena 21.0 (GPT-4o wins here, 26.7), **AssistantBench 5.2**. → [arXiv 2412.05467, Dec 2024](https://arxiv.org/html/2412.05467v1). AssistantBench single digits is the honest read on open-web multi-hop.

**Mind2Web 2** → 130 long-horizon agentic-search tasks, tree-structured rubric compiled into a per-task judge agent scoring answer correctness *and source attribution*. Best system (OpenAI Deep Research) reaches **50–70% of human performance at half the time**; Deep-Research systems beat Operator-style web agents because they stay on-task over long horizons. → [arXiv 2506.21506, Jun 2025, NeurIPS 2025](https://arxiv.org/abs/2506.21506).

**WebVoyager** → 643 tasks / 15 sites, GPT-4V + Set-of-Mark: **59.1%**, GPT-4V autorater **85.3%** human agreement. → [arXiv 2401.13919, ACL 2024](https://arxiv.org/abs/2401.13919).

## 2. Observation format

**AgentOccam** is the single most useful ablation in the literature. Full WebArena ablation → Vanilla **16.5%** → +reduced action space **25.8%** → +disable X-scrolling **30.0%** → +observation optimisation **34.7%** → +history replay **36.8%** → full AgentOccam **43.1%**. Per-site final: Reddit 61.3, Map 46.8, Shopping-Admin 45.6, Shopping 40.6, GitLab 37.8, multi-site 14.6. Crucially, **observation tokens/step did not drop** — 2,210 (vanilla) → 1,652 (after action reduction) → 2,891 (after obs optimisation) → 2,931 (final). Steps/task 6.2 → 9.0. So "simplify the observation" here means *align the format with reading-comprehension-shaped input* (merge static text with interactive links, markdown-ify, drop redundant containers), not merely shrink it. No in-context examples, no search, no online feedback. → [arXiv 2410.13825, ICLR 2025](https://arxiv.org/abs/2410.13825); [repo](https://github.com/amazon-science/AgentOccam) (actions: `branch`, `prune`, `click`, `type`, `stop`, `note`, `go_back`).

**Agent-E** → three swappable DOM distillations (`text_only` for reading, `input_fields` for forms, `all_fields` preserving parent-child), chosen per sub-task by the browser-nav agent. **73.1% on WebVoyager** (WolframAlpha 95.7, Google Search 90.7, Maps 87.8 … Booking.com 27.3, Google Flights 35.7); +20pp over WILBUR (52.6), +16pp over WebVoyager's multimodal agent (57.1). ~150s per successful task, ~220s per failure; 25 LLM calls/task (6.4 planner, 18.6 navigator). Paper is explicit that it has **no component-removal ablation** — design principles came from dev experience. → [arXiv 2407.13032, Jul 2024](https://arxiv.org/html/2407.13032v1).

**SeeAct** → separates action *generation* from *grounding*; three grounding strategies (element attributes, textual choice, image annotation). GPT-4V with **oracle grounding** substantially beats everything, but the best real grounding strategy sits **20–25pp below oracle**; image annotation works on simple pages and degrades on complex ones. Up to **50% on live sites with oracle grounding**. → [arXiv 2401.01614, Jan 2024](https://arxiv.org/abs/2401.01614).

**Region4Web / PageDigest** (2026) → segment the page into semantic *regions*, select a region, then digest it. WebArena: GPT-5.1 45.2→**47.5**, Gemini 3.1 Flash-Lite 39.4→41.6, DeepSeek-V3.2 40.4→**43.4**, Qwen3.5-27B 38.2→39.9 (avg **+2.3pp**) with **43% fewer observation tokens** (6,437→3,671; Qwen −54%). WebArena-Lite ablation: baseline 48.5% / 5,410 tok → region-only 50.3% / 5,922 → +PageDigest **53.9% / 3,814**. Failure attribution: 90% actor/backbone, only 10% region selection. → [arXiv 2605.07134, May 2026](https://arxiv.org/html/2605.07134).

**Hybrid a11y-primary + selective vision** is the converged production answer. A 100-line HTML form field compresses to a few a11y lines; Stagehand reports **80–90% size reduction vs raw DOM** by using Chrome's accessibility tree via Playwright ([browserbase/stagehand](https://github.com/browserbase/stagehand)). Playwright MCP returns a YAML a11y tree where each element carries an opaque `ref` (`ref=e5`, iframe-qualified `f1e12`); snapshots reported at **~200–400 tokens** for simple pages vs thousands for DOM dumps ([playwright.dev/mcp/snapshots](https://playwright.dev/mcp/snapshots)). Skyvern pairs an annotated screenshot with a structured interactable-element description; it measured **HTML-format element description vs JSON: −11% tokens, +3.9% success** ([skyvern.com blog](https://www.skyvern.com/blog/how-skyvern-reads-and-understands-the-web/)). Grid-coordinate observation was tried and abandoned; SoM annotation "works when there are only a handful of interactive elements" and clutters otherwise. → [arXiv 2511.19477, Nov 2025](https://arxiv.org/html/2511.19477v1).

## 3. Action space

- **Fewer, higher-level actions beat richer ones.** AgentOccam's single largest ablation jump is action-space reduction alone: **16.5 → 25.8% (+9.3pp)**, before any observation work. Disabling horizontal scrolling alone added **+4.2pp**. It also added two *non-browser* actions — `note` (write a fact to a scratchpad) and `branch`/`prune` (self-managed plan tree). → 2410.13825.
- **Code-as-action / API actions.** Beyond Browsing (WebArena): browsing-only **14.8%**, API-only **29.2%**, hybrid interleaved **38.9%** (GitLab 44.4, Reddit 51.9, Map 45.9). Steps: 8.4 / 7.8 / 8.5; cost $0.1 / $1.2 / $1.4 per task. Hybrid = **+24pp absolute over browsing alone**. → [arXiv 2410.16464, Oct 2024](https://arxiv.org/html/2410.16464v3). CoAct-1 (GUI operator + programmer agent under an orchestrator) **60.76% vs 53.1% GUI-only** ([arXiv 2508.03923](https://arxiv.org/html/2508.03923v1)).
- **Batched/bulk actions.** On a 28-field form: **10 vs 38 tool calls (−74%), 104.5s vs 245.1s (−57%), 154K vs 260K tokens (−41%)**. → 2511.19477.
- **Stale references.** Versioned element IDs (`<version>:<index>`, version = snapshot epoch); the tool validates the version at execution and **fails safely** on mismatch instead of clicking the wrong thing (2511.19477). Playwright MCP uses opaque per-snapshot refs; browser-use guidance is re-query the DOM fresh before every click/type rather than carrying indices across steps ([theneuralbase.com browser-use course](https://theneuralbase.com/browser-use/learn/intermediate/stability-across-renders/)).
- **Plan-then-execute**: commit a task program before touching untrusted content, so page content affects data flow but never control flow; **80% of WebArena tasks need no runtime LLM calls** under this paradigm, which also makes programs cacheable and debuggable. Cost: needs per-site trusted APIs. → [arXiv 2605.14290, May 2026](https://arxiv.org/html/2605.14290).

## 4. Open-source harness architecture

| Harness | Perception | Loop | Context bounding | Verification |
|---|---|---|---|---|
| **browser-use** | screenshot + filtered a11y/DOM tree of interactive elements with indices | capture state → LLM with action list → parse into Playwright calls → repeat; pluggable `Tools` registry | known failure mode: context overflow on complex pages; open issues on serializer dropping visible elements ([#5629](https://github.com/browser-use/browser-use/issues/5629)) | `history.final_result()`; own "Bench V2" on a 60-task subset scored by rubric, reported as mean rubric score × cost/task ([repo](https://github.com/browser-use/browser-use)) |
| **Stagehand** | Chrome a11y tree via Playwright, scopable to a selector; 80–90% smaller than DOM | atomic `act`/`extract`/`observe` primitives + an optional Agent loop | selector-scoped snapshots so out-of-container changes don't bust the cache | server-side + local action cache keyed on instruction + page content + URL; **dynamic URLs break the cache key** ([docs](https://docs.stagehand.dev/v3/best-practices/caching)) |
| **Skyvern** | viewport screenshot + simplified interactable element tree w/ labels+positions | Skyvern 2.0 = Planner → Actor → **Validator** (triggers replan) | per-step artifacts: annotated screenshots, element tree, prompts, LLM req/resp | explicit Validator agent in the loop ([docs](https://www.skyvern.com/docs/cloud/getting-started/introduction)) |
| **Playwright MCP** | a11y snapshot with `ref` per element | stateless MCP tools (`browser_snapshot`, `browser_navigate/click/type`, ~30–70 total) | refs are per-snapshot → implicit epoch invalidation | none built in |
| **BrowserGym/AgentLab** | raw DOM **and** AXTree, each element enriched with a `bid`, bounding box, **visibility ratio**; screenshot with pixel-accurate element mapping; **multi-tab state** (URLs, titles, active index); error feedback from failed actions | gym-style step loop; action space from raw Python/Playwright up to restricted `click()/type()/press()` primitives | leaves formatting to the agent, deliberately | benchmark harness, not agent-side ([2412.05467](https://arxiv.org/html/2412.05467v1)) |

**Context bounding, measured**: keep only the most recent snapshot, LLM-trim older ones, compress history → full history grows linearly to **>43,000 tokens after 15 actions**; compressed history **stabilises ~12,600**. Intelligent trimming cut cost **57%** on long tasks despite **+34% tool calls** from occasional re-requests. A 30-step price-comparison task: **$0.1454 total, 74.9% of input tokens cache-hit, $0.0048 / 8,958 tokens / 6.8s per step**. Same system: **~85% on WebGames (53 challenges)** vs ~50% prior agents, 95.7% human. → 2511.19477.

## 5. Known hard problems

- **Stale refs** → version-stamped refs that hard-fail on mismatch (2511.19477); fresh DOM re-query per action (browser-use); attribute selectors (`[data-testid]`) over positional.
- **Dynamic pages** → Agent-E's **change observation**: after each action, diff state via MutationObserver + attribute changes (e.g. `aria-expanded`) and feed a *verbal* description of the change back to the agent; cited as the fix for flight/booking widgets (2407.13032).
- **Pagination / infinite scroll / structured extraction** → WebLists ([arXiv 2504.12682, Apr 2025](https://arxiv.org/pdf/2504.12682)) benchmarks list extraction over 50 enterprise sites, capped at 5 pages/task, precisely because agents fail on multi-page completeness. AgentOccam's cheap win here was *disabling a scroll axis* (+4.2pp).
- **Login/CAPTCHA/consent** → no published solve. Prompt injection succeeded **73.2%** with no defenses, **8.7%** with layered defenses across 7 LLMs; "infrastructure does not solve CAPTCHAs, which can still be a hard stop" ([TinyFish](https://www.tinyfish.ai/blog/browser-agent-security-risk), [Wiz 2025 review](https://www.wiz.io/blog/agentic-browser-security-2025-year-end-review)). Operator was hit by "Task Injection" via a fake CAPTCHA that triggered a download. Deterministic keyword gate ("refund", "delete", "transfer", "password") forces human confirmation in code, not LLM judgment (2511.19477).
- **False success / self-verification** → agents assert completion against failing state in **45–48% of failures** in single-control τ²-bench domains and **75.8%** of AppWorld self-assessing trajectories. Judge de-anchoring (force the judge to produce its *own* answer before seeing the candidate's) drops false-positive rate **0.719 → 0.012**. → [arXiv 2606.09863, Jun 2026](https://arxiv.org/html/2606.09863).

## 6. Skill / memory reuse

- **Agent Workflow Memory** → induce reusable workflows from trajectories (neural induction yields **7.3–7.4 workflows per example**), retrieve selectively into the prompt; offline (from train set) or online (from test queries on the fly). **WebArena +51.1% relative SR**, beating even human-expert-written workflows by 7.9%; **Mind2Web +24.6% relative step SR**; online AWM widens its lead by **8.9–14.0 absolute points** as train/test distribution gap grows, and reduces steps to success. → [arXiv 2409.07429, Sep 2024](https://arxiv.org/abs/2409.07429).
- **SkillWeaver** → agent explores a new site, practises, and distils experience into **plug-and-play API functions**. **+31.8% relative on WebArena, +39.8% on real sites**; APIs synthesised by a strong agent transferred to a weak agent give **up to +54.3%**. → [arXiv 2504.07079, Apr 2025](https://arxiv.org/abs/2504.07079).
- **ICAL** → VLM abstracts noisy demos into programs annotated with task relationships, object state changes, temporal subgoals, task construals; refined by human feedback; used as retrieval exemplars. **VisualWebArena 14.3% → 22.7%**; retrieval-augmented GPT-4V **1.6×**, fine-tuned Qwen2-VL **2.8×**. → [arXiv 2406.14596, Jun 2024](https://arxiv.org/abs/2406.14596v1).

## Five design choices to copy (from 55% on a 60-task Online-Mind2Web gate)

1. **Cut the action space before touching anything else.** AgentOccam got **+9.3pp from action reduction alone** and **+4.2pp from disabling one scroll axis**. Ship: `click / type / select / scroll-Y / go_back / navigate / note / answer`. Delete hover, x-scroll, tab-management-as-an-action, and any action you can't name a failing task for. Cheapest pp/hour in this entire brief.
2. **A11y-tree-primary observation with a region/viewport digest, screenshots only on demand.** Region4Web: **+2.3pp average and −43% tokens**; Stagehand: 80–90% smaller than DOM; Skyvern: HTML-shaped element descriptions beat JSON by **−11% tokens / +3.9% SR**. In a Chrome extension you have direct DOM + `chrome.automation`; use it.
3. **Version-stamped element refs that fail loudly.** `epoch:index`, validated at execution, refusing on mismatch (2511.19477). Turns your silent wrong-clicks into retriable errors — and wrong-clicks are exactly what produces the "failures take 2× the steps" pattern in 2504.01382.
4. **Compress history, keep one live snapshot.** 43K→12.6K tokens at 15 actions, **−57% cost** on long tasks. Your hard-task bucket (≥11 steps, where Operator drops to 43.2%) is where context bloat bites.
5. **A separate WebJudge-shaped self-check before `answer`.** Key points → key screenshots/state → verdict, with the verifier producing its own answer first (de-anchoring: FP 0.719→0.012). Gate `answer` on it; on FAIL, continue rather than declare success. This directly attacks the 45–75% false-success band.

## Three not to copy

1. **MCTS / tree search over live pages** (WebPilot 37.2% on WebArena). It needs cheap resets. A Chrome extension on a user's real logged-in tab cannot undo a submitted form, and rollout cost is multiples of a single trajectory. Take `branch`/`prune` as *prompt-level* plan bookkeeping instead — AgentOccam got there without search.
2. **Screenshot/SoM-first perception.** WebVoyager's 59.1% with SoM has been beaten by text-first Agent-E at 73.1%; SoM "clutters on complex layouts", grid-coordinate variants were abandoned, and SeeAct shows image annotation degrading on complex pages. Keep vision as a fallback for canvas/non-accessible widgets only.
3. **Self-reported leaderboard scores as your target.** The 97% / 93% entries use custom or differing judges; the same Navigator agent reads 78.7% human vs 64.7% WebJudge. Fix your judge (o4-mini WebJudge, factual-actions-only history, no Google start) and track *your* 60-task number over time; chasing the public board optimises the judge, not the agent. Same reason not to copy Agent-E's stack wholesale — the paper states it has no component ablations, so you can't tell which part earned the 73.1%.

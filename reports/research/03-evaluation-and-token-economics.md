## (a) Evaluation

**1. LLM-as-judge: rubric design and citation-backed judging**

*Practice → mechanism.* The strongest current pattern is not "score 1–5". It is a **tree-structured rubric decomposed into binary leaf nodes**, where each leaf is executed by a small judge *program* (verify-a-statement, verify-by-URL) and internal nodes aggregate with explicit logic. Mind2Web 2 splits every answer into *correctness* and *attribution*, and marks URL-verification nodes `critical` rather than `optional` so an unsourced claim cannot be averaged away. *Measured effect:* node-level human audit of 720 rubric nodes found only 7 genuine judge errors — **99.03% accuracy**, versus sub-90% for prior automated web-task evaluators. *Source:* Mind2Web 2, arXiv:2506.21506 (Jun 2025; NeurIPS 2025) — https://arxiv.org/abs/2506.21506

*Practice → mechanism.* For trajectory judging, **evidence selection beats whole-trace dumping**. WebJudge extracts task "key points" first, then filters to the crucial screenshots and judges only those, which both shortens the judge's context and forces it to cite evidence. *Measured effect:* **85.7% agreement with human labels** (o4-mini backbone) and a success-rate gap of 3.8pp, vs 79.4% autonomous-eval, 73.9% WebVoyager-style, 66.9% AgentTrek; a fine-tuned WebJudge-7B reaches ~87%. *Source:* "An Illusion of Progress?", arXiv:2504.01382 (Apr 2025) — https://arxiv.org/abs/2504.01382 ; code https://github.com/OSU-NLP-Group/Online-Mind2Web

*Practice → mechanism.* **Pairwise scoring is cheaper to calibrate but carries position bias**; absolute scoring carries verbosity and calibration drift. Position bias is not noise — it is systematic per judge/task and scales with the quality gap between candidates, so it must be measured by swapping order, not prompted away. *Measured effect / source:* "Judging the Judges: A Systematic Study of Position Bias", arXiv:2406.07791 (Jun 2024) — https://arxiv.org/abs/2406.07791. On self-preference, ~90% of apparent self-favouring is attributable to **evaluator uncertainty** rather than identity, i.e. it concentrates where the judge cannot tell quality apart — arXiv:2506.02592 (Jun 2025) — https://arxiv.org/abs/2506.02592. Practical implication: judge disagreement is a *signal that your rubric leaf is underspecified*, not a reason to swap models.

**2. Metrics beyond success rate**

*Practice → mechanism.* **Cost-controlled evaluation**: report accuracy on a cost–accuracy Pareto frontier, not at any price. Kapoor et al. show trivial baselines (retry, warming, escalation) Pareto-dominate Reflexion/LDB/LATS on HumanEval at up to **50× lower cost**, meaning much reported "agent progress" is purchased inference. *Source:* "AI Agents That Matter", arXiv:2407.01502 (Jul 2024, TMLR) — https://arxiv.org/abs/2407.01502

*Practice → mechanism.* **pass^k over pass@k.** pass@k is `1 − C(n−c,k)/C(n,k)` and measures *capability* (best-of-k); pass^k is the probability all k independent attempts succeed and measures *reliability*. *Measured effect:* on τ-bench, a GPT-4o agent above 60% pass@1 falls **below 25% at pass^8**. *Source:* τ-bench, arXiv:2406.12045 (Jun 2024) — https://arxiv.org/abs/2406.12045

*Practice → mechanism.* **Token spend is the dominant covariate.** On BrowseComp, Anthropic found token usage alone explains **80% of performance variance**, and token usage + tool-call count + model choice explain 95%. Any eval that does not hold tokens roughly constant is partly measuring budget. *Source:* Anthropic, "How we built our multi-agent research system" (Jun 2025) — https://www.anthropic.com/engineering/built-multi-agent-research-system

*Practice → mechanism.* **Site drift is a first-class confounder.** WebArena is self-hosted and reproducible; WebVoyager/Online-Mind2Web run on live sites and therefore absorb UI changes, anti-bot behaviour and answers that change week to week. Both are end-to-end binary — no partial credit, no precision/recall — so intermediate reasonableness is invisible. *Source:* arXiv:2504.01382 §task-drift discussion; WebArena/WebVoyager comparisons via https://leaderboard.steel.dev/leaderboards/webvoyager/ (accessed Sep 2026). Mitigation used by Online-Mind2Web: periodic task re-validation and removal of tasks whose ground truth has drifted.

**3. Regression testing**

*Practice → mechanism.* **Record–replay over golden traces.** Capture production traces (tool calls + observations), then re-run *your current agent code* against the recording, answering every tool call from the tape. This isolates prompt/model changes from site nondeterminism. Standard discipline: prove the unchanged replay reproduces first, then run the candidate. *Practice:* **CI gating on quality and cost** — a GitHub Action runs the eval set per PR and blocks merges below threshold. *Source:* Braintrust docs, https://www.braintrust.dev/docs/evaluate and https://www.braintrust.dev/articles/agent-observability-complete-guide-2026 (accessed Sep 2026). *Flake management:* agent evals inherit flaky-test economics (~16% of tests flaky at Google scale) plus probabilistic scoring, so thresholds must be set on repeated-run distributions, not single runs.

**4. Research-agent evaluation**

*Practice → mechanism.* **Separate report quality from retrieval honesty.** DeepResearch Bench (100 PhD-level tasks, 22 fields) runs two frameworks: RACE generates task-adaptive criteria across comprehensiveness / depth / instruction-following / readability, and **FACT** extracts every statement–URL pair, dedupes per URL, **actually fetches the cited page**, and issues a binary support decision — yielding *citation accuracy* (precision) and *effective citations* (supported pairs per task). *Source:* arXiv:2506.11763 (Jun 2025) — https://deepresearch-bench.github.io/

*Practice → mechanism.* **Atomic-fact decomposition** for factual accuracy sampling: split the report into atomic facts, score the fraction supported by a trusted source. FActScore's automated estimator tracks human FActScore with **<2% error**. *Source:* arXiv:2305.14251, EMNLP 2023 — https://github.com/shmsw25/factscore. RAGAS gives the cheap production analogue: *faithfulness* (claims entailed by retrieved context) and *factual correctness* in precision/recall/F1 modes — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/

## (b) Token economics

**5. Prompt caching**

*Anthropic (primary, accessed Sep 2026 — https://platform.claude.com/docs/en/build-with-claude/prompt-caching):* writes cost **1.25×** input at 5-min TTL, **2×** at 1-hour; reads cost **0.1×**. Minimum cacheable prefix is model-dependent (512 / 1,024 / 2,048 / 4,096 tokens); under-minimum prompts silently don't cache. Max **4 breakpoints**, with a 20-block lookback each. The prefix is strictly ordered **`tools` → `system` → `messages`**: changing tool definitions invalidates *everything*; toggling web-search/citations or the speed setting invalidates system+messages; `tool_choice` and adding/removing *any* image invalidate messages only. TTL is measured **from the start of the writing request**, so a 4-minute streamed response leaves ~1 minute of a 5-minute TTL. Reads refresh the TTL for free and **do not count against rate limits**.

*OpenAI:* automatic, no opt-in, prefixes ≥**1,024 tokens**, 5–10 minute eligibility window, **50%** discount on cached input on most models (up to 75% on the newest). https://developers.openai.com/api/docs/guides/prompt-caching and https://openai.com/index/api-prompt-caching/

*Google:* **implicit** caching is on by default with no write or storage charge; **explicit** caching is declared and adds storage rent. Implicit minimums are 2,048 tokens (Gemini 2.5 class) rising to 4,096 on newer Flash/Pro. Cached reads are heavily discounted (~90% off for explicit hits); storage is reported at roughly $1/M-tokens/hour (Flash) to $4.50 (Pro) — *this figure is secondary, I could not load the Vertex pricing table*. https://ai.google.dev/gemini-api/docs/caching

*Measured effect in the wild:* Manus reports KV-cache hit rate as "the single most important metric" for a production agent, with a ~**100:1 input:output ratio** and a 10× unit-price gap between cached and uncached input; their rules are: never put a second-precision timestamp in the system prompt, keep context **append-only**, and **mask tool logits instead of mutating the tool list**. https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus (Jul 2025)

**6. Context strategy in long runs**

*Mechanism → effect.* Unmanaged agent context grows super-linearly from tool output: Anthropic documents a research agent reaching **335,279 tokens over 5 turns with 96.3% of it file-read results**, hard-stopping mid-task. Their three levers are **compaction** (a 5-ticket pipeline compacted **208K → 86K tokens, −58.6%**), **structured note-taking to files** (the Pokémon agent held objectives across context resets), and sub-agents with private windows. Tool-result clearing is the lightest form and ships as a platform feature. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents (Sep 2025)

*Why this is a quality lever, not just a cost lever:* Chroma tested 18 frontier models and found **every one degrades monotonically with input length**, on tasks as simple as retrieval and replication, with distractors and haystack structure mattering more as length grows. Trimming context buys accuracy *and* money. https://www.trychroma.com/research/context-rot (2025)

**7. Model routing**

*Mechanism → effect.* RouteLLM trains routers on Chatbot Arena preference data to decide per-query whether the strong model is needed. Matrix-factorisation router: **95% of GPT-4 quality on MT-Bench at ~85% cost reduction**, routing only ~14–26% of queries to the strong model; a BERT classifier gets ~45% savings on MMLU. https://arxiv.org/abs/2406.18665 (Jul 2024), https://www.lmsys.org/blog/2024-07-01-routellm/. *Where it loses:* those are ceilings on chat-style distributions with a trained router; independent aggregation of routing benchmarks puts realistic production savings nearer **~35% at <2% quality loss**, and routing degrades exactly where the router's uncertainty is highest — long-horizon planning and multi-step tool decisions, i.e. the planner. Route *extraction and classification* down; never route the planner down blind.

**8. Observation-size control**

*Mechanism → effect.* Observation format dominates browser-agent cost. Reported figures: a full unfiltered accessibility-tree dump can exceed **100,000 tokens** on one page (Playwright MCP measured at **114,000 tokens** for a single page), a semantically filtered AX tree ~**15,000**, raw DOM ~**8,000**, and compact element references ~**3,000 tokens for a whole 10-step task** — a ~97% reduction with no model change. Screenshots sit at ~1,000–2,000 tokens for a 1280×800 frame on most vision models, so a *single* screenshot is cheap but a screenshot *per step* plus its retained history is not, and DOM-native execution also cut per-action latency from 2–5s to <500ms. https://getnadir.com/blog/browser-agent-token-cost-screenshots-accessibility-tree/ and https://dev.to/siropkin/accessibility-tree-vs-screenshots-the-token-math-behind-my-browser-agent-3fk9 (accessed Sep 2026 — engineering write-ups, not peer-reviewed; the 114k figure is reproducible against Playwright MCP, the 3k figure is vendor-favourable).

## Adopt these evaluation practices

1. **Tree rubrics with binary leaves**, attribution nodes marked critical (Mind2Web 2 pattern) — for the research agent, every factual claim gets a `verify_by_url` leaf that actually fetches.
2. **WebJudge-style evidence filtering** for the browser agent: extract key points from the task, judge only the screenshots/steps that touch them. Budget ~85% human agreement, and hold out ~100 human-labelled trajectories to measure *your* judge's agreement rather than inheriting the paper's.
3. **Order-swap every pairwise judgment** and report the flip rate as a judge-health metric; treat high flip rate as an underspecified rubric leaf.
4. **pass^k at k=3–5** as the headline reliability number; keep pass@1 only as a capability ceiling.
5. **Report cost-per-success and steps-per-success** on the same chart as accuracy; a change that raises success 2pp and cost 40% is a regression.
6. **Two eval tiers**: a frozen fixture-site / record-replay tier that gates CI deterministically, and a live-site tier run on a schedule with re-validated ground truth and explicit task-drift retirement.
7. **CI gates on quality *and* median tokens-per-task**, thresholds set from repeated-run distributions (≥3 seeds) so flake doesn't block merges.
8. **Research agent**: FACT-style citation precision + effective-citation count, plus FActScore-style atomic-fact sampling on a random 10% of reports. Track hallucinated-citation rate (cited URL that does not support the claim, and cited URL that 404s) as a separate, zero-tolerance metric.

## Token practices for your run (247k input / 22.8 calls / 41.2% resent prefix / planner cache 1.6%)

1. **Fix the planner cache first — this is a bug, not a tuning knob.** The navigator at 98% proves the plumbing works. At 1.6%, the planner's prefix is mutating every call. Check, in this order, against the invalidation hierarchy: (a) a **changing tool array** (any add/remove/reorder/description edit nukes the entire cache — mask instead of mutate); (b) a **timestamp, step counter, token budget, or retry count** in the system prompt; (c) **injected summaries prepended** rather than appended; (d) **images added/removed** between planner calls, which invalidates all message blocks; (e) **>5 minutes between planner calls** — TTL counts from request start, so a planner that thinks while navigators run will expire. Expected payoff: the static prefix is ~101.8k tokens/task; moving the planner's share from 1.6% to ~90% hit rate takes those tokens from 1.0× to 0.1×, worth roughly **30–40% of total input spend** depending on the planner/navigator split.
2. **Set `ttl: "1h"` on the planner prefix only.** The 2× write premium pays back after ~5–7 reads; a planner called ~5–10 times per task with multi-minute gaps between calls is exactly the sporadic pattern the 5-minute TTL fails. Leave the navigator on 5-minute — it is already at 98%.
3. **Use ≤4 breakpoints deliberately**: one after `tools`, one after the static system prompt, one after the task description, one floating at the end of the stable message history. Don't scatter them.
4. **Kill raw-observation retention.** Keep the *current* observation verbatim; replace all prior ones with a one-line structured extract (URL, action taken, outcome, extracted fields). At 22.8 calls, retained observations are the compounding term.
5. **Send diffs, not pages.** After the first observation of a URL, send only the changed subtree/element list. Compact element references over AX-tree dumps — that's the 114k → 3k axis.
6. **Screenshots on demand only** — as a disambiguation tool the planner can request, never as a per-step default, and never retained past the step that used it.
7. **Compact at a threshold, don't roll a window.** Anthropic's 208K → 86K compaction shows structured summarisation keeps the causal chain that a naive rolling window drops; pair it with file-backed notes so the agent can re-read detail instead of carrying it.
8. **Route extraction/classification to a cheap model** (field extraction from a page, "is this the right result?", link triage) and keep planning on the strong model. Budget ~35% savings at <2% loss on the routed portion; instrument per-subtask accuracy before and after, because routing failures show up as *more steps*, not as visible errors.

**250-word summary.** Serious agent evaluation has converged on four things. Judges are programs, not scores: Mind2Web 2 decomposes each task into a tree of binary rubric leaves with URL-verification nodes marked critical, audited at 99.03% node accuracy; WebJudge filters to task-relevant screenshots before judging and hits 85.7% human agreement. Judge bias is measurable, not preventable — position bias is systematic, and ~90% of apparent self-preference is really evaluator uncertainty, so order-swapping and human-calibrated holdouts are mandatory. Metrics must include cost: simple baselines Pareto-dominate SOTA agents at 50× lower cost, token spend alone explains 80% of BrowseComp variance, and pass^8 drops a 60%-pass@1 τ-bench agent below 25%. Regression testing means record-replay over golden traces with CI gating on quality and cost. Research agents need FACT-style fetch-and-verify citation precision plus FActScore atomic-fact sampling.

On tokens: Anthropic caches at 1.25×/2× write and 0.1× read with a strict tools→system→messages prefix, 4 breakpoints, and TTL counted from request start; OpenAI is automatic at ≥1,024 tokens for 50–75% off; Google splits implicit (free writes) from explicit (storage rent). Context management is a quality lever too — every one of 18 models degrades with length, and Anthropic's compaction cut 208K→86K tokens. Routing saves ~35% at <2% loss realistically. Observation format dominates browser cost: 114k tokens per page for an AX dump versus ~3k for a whole task with compact element refs.

Your 1.6% planner cache hit rate is a prefix-mutation bug — most likely a changing tool array or a timestamp — and fixing it alone is worth roughly a third of your input spend.
